Nav: a terminal-style wordmark, a search field, up to three text links the site supplies and one text button that switches the theme ("Theme: Dark" / "Theme: Light", always the last item of the link group). No dropdowns, no icons.

```jsx
<Nav active="writing" />
<Nav active="posts" links={[{ key: 'posts', label: 'Posts', href: '/blogs/' }, { key: 'about', label: 'About', href: '/about/' }]} />
<Nav active={null} query="gitops" />  {/* the /search page: no current link, text kept in the field */}
```

Links: the examples (Writing, About, Consulting) are examples. The site supplies its own, one word each. A page the site does not have is left out, never a dead link. A fourth link needs a new measurement of the widths below. Secondary lists (Archive, Tags, RSS) go in the Footer.

Static, never sticky or fixed, and as wide as wide content (`content-width-wide`, 1040px, centered), the same as the Footer. Every item has a 44px hit area: the box is the label plus `space-2` each side and 44px tall, and a pseudo-element widens the target for short labels. Items are `space-1` apart (20px between labels, the same for every pair), and the link group is pulled out by `space-2` so the first and last label sit on the content edge, in line with the wordmark. On hover (hover devices only) and press an item gets a `surface-hover` fill and a non-current label goes to `text-primary` (at least 2:1 from `text-secondary`); the current item keeps `text-primary` and shows the fill only, so the hover cue never collides with its 2px `accent` rule. Press has no transition on the way in; the fade runs on release. The wordmark takes the fill plus an underline. The current page has `aria-current="page"`. The Nav has no horizontal padding of its own, so the page padding applies to it. If the row does not fit it wraps under the wordmark, and the link group wraps too. Measured for the default three links with the real fonts and the longer "Theme: Light" label, at 24px page padding: one row from 629px up, two rows from 356px, three rows below 356px. Two links fit one row at a smaller width. No hamburger. The `<nav>` is labeled "Main". The theme button shows the current theme ("Theme: Dark") and its accessible name adds the action ("Theme: Dark. Switch to light."); the visible text stays at the start of the name. It reads and stores the choice through `theme.js`; put `themeInitScript` inline in `<head>` so there is no flash, and `themeNoScriptCss` in `<noscript><style>` so the button is hidden when JavaScript is off.

Search: a `<form role="search" action="/search">` with one `type="search"` field named `q` (`aria-label="Search the writing"`, placeholder "Search"), placed after the wordmark and before the links in the DOM. It is the only search field on the page, the results page included. It is narrow at rest. While it has focus it grows to the right, never below its resting size (`flex-basis` and `min-width` 7rem). From the one-row width of the site's own Nav the link group is visually hidden, by clipping, not `display: none` or `visibility: hidden`: the links stay focusable, Tab from the field reaches the first link and the links come back. The one-row width is a measurement of the site's own Nav, not a constant. The rule: the smallest width W such that every width from W up fits on one row, found by scanning from wide to narrow and stopping at the first width that needs two rows, rounded up by about 8px. Page padding steps down at 480px, so a Nav can fit one row just below 480px, need two just above and fit again further up; do not take the first width that fits. For the default three links W is 629px and `core.css` uses 640px. Too high is harmless, too low makes the Nav shrink on focus and shifts the page. Below it the links stay and only the field grows. Escape leaves the field and changes nothing else: the text and any results stay. The change is instant, with no animation. The rules live in `core.css` (`.pl-search`, `.pl-field`). See the README, Search, for the checks to run.
